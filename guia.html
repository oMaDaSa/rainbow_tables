Rainbow Tables
em Python

O professor pede que vocês implementem uma Rainbow Table e experimentem mudar seu formato. Neste guia, vamos partir de uma cadeia pequena, entender como a busca funciona e escrever as funções necessárias. Depois vocês vão usar o programa para comparar as tabelas e discutir os resultados.

Estado em 18/10/2026: a base conjunta (B1/B2) e a parte A (A1/A2) estão implementadas. A parte B, índice e busca em busca.py, continua no esqueleto original para a outra pessoa completar. Consulte o README atualizado para conferir os 13 testes deste escopo. As instruções abaixo foram preservadas para acompanhar o código e continuar a parte B.
Comecem pelas etapas 0–4 juntos. Depois, uma pessoa fica com a construção e a outra com a busca. As duas partes estão explicadas aqui: vale ler a do colega também, mesmo que vocês dividam o código.

Usaremos Python 3.10 ou mais novo, sem instalar bibliotecas adicionais. As páginas citadas são do PDF da aula de Ivan Sendin, de 13/10/2026. O guia e a lista de palavras podem ser usados sem internet.

Etapa 0 · juntos

O que o trabalho pede

Imaginem que temos o hash de uma senha e sabemos que ela foi escolhida da lista Diceware. Poderíamos testar todas as palavras até encontrar uma que produza esse hash. Outra possibilidade seria calcular os hashes de todas elas antes e guardar tudo, mas isso ocupa espaço.

A Rainbow Table fica entre essas duas opções. Antes das buscas, construímos sequências chamadas cadeias e guardamos só o início e o fim de cada uma. Quando recebemos um hash para procurar, refazemos alguns trechos. É daí que vem a troca entre memória e tempo discutida na aula: economizamos espaço, mas precisamos recalcular parte do que foi descartado.

Para começar, vamos trabalhar com senhas de uma palavra. Isso dá 7.776 possibilidades e permite fazer os experimentos num computador comum. Mais adiante há uma seção sobre duas palavras. O PDF pede senhas pequenas, mas não fixa a quantidade de palavras nem os parâmetros dos testes; os valores sugeridos aqui são escolhas para organizar o experimento.

Como dividir entre vocês

Primeiro, façam juntos a leitura da lista, o hash e a redução. As duas partes vão usar essas funções, então precisam concordar sobre o que elas recebem e devolvem. Depois, quem ficar com a parte A escreve a construção das tabelas. Quem ficar com a parte B escreve a busca. Para juntar, A entrega uma lista de pares início/fim, e B usa essa lista para procurar os hashes.

Ao terminar, vocês devem conseguir rodar o programa, conferir se ele recupera hashes presentes nas cadeias e medir quantos alvos aleatórios cada tabela encontra. Esses resultados, junto com a descrição do computador, dão o material para discutir altura, largura e custo de busca no relatório.

Carregando a lista Diceware

Ligação com a aula: p. 46; revisão da questão Diceware do guia da prova.

Vocês já viram Diceware no material da prova: cinco lançamentos de um dado de seis faces formam um código, e esse código escolhe uma entrada da lista. São 6⁵ = 7.776 códigos possíveis. Abram dados/diceware.wordlist.asc no VS Code para ver o arquivo que o professor indicou.

As primeiras linhas incluem 11111 → a e 11112 → a&p; a última entrada é 66666 → @. Apesar de chamarmos de “palavras”, a lista também contém números e símbolos. Precisamos preservá-los como estão.

No nosso programa, o código dos dados só serve para organizar a lista. A senha é o texto associado a ele. Para a entrada 11112 a&p, por exemplo, calculamos o hash de a&p, sem o código nem a quebra de linha. Para sortear senhas, basta escolher entradas da lista com a mesma chance; simular os dados daria o mesmo tipo de escolha.

Implementem em base.py · carregar_palavras
  1. Leiam o arquivo com caminho.read_text(encoding="utf-8") e separem em linhas com .splitlines().
  2. Considerem válida uma linha com dois campos: código de cinco caracteres, todos entre 1 e 6, e palavra. Linhas PGP são ignoradas.
  3. Guardem código e palavra; detectem códigos duplicados antes de sobrescrever qualquer registro. Ordenem pelo código.
  4. Exijam 7.776 códigos distintos e 7.776 palavras distintas. Se a lista estiver incompleta ou duplicada, usem raise ValueError("mensagem explicativa").
  5. Devolvam somente a lista de palavras na ordem combinada.

O caminho do arquivo já está definido em base.py, usando Path, que é a classe do Python para trabalhar com caminhos. Assim, chamar carregar_palavras() sem argumentos deve carregar a cópia em dados/, inclusive no computador do colega.

Dica 1 · separar campos e ignorar PGP

linha.split() separa por espaços ou tabulações e descarta espaços externos. Verifique a quantidade de campos antes de acessar as posições. Depois confira o comprimento do código e cada caractere. O cabeçalho e a assinatura do arquivo não cumprem esse padrão.

Dica 2 · ordenar sem modificar as palavras

Um dicionário codigo_para_palavra permite detectar código já visto com codigo in codigo_para_palavra. Para percorrer os códigos em ordem, use sorted(codigo_para_palavra). Como todos têm cinco dígitos, a ordenação textual serve. Não aplique remoção de acentos, pontuação ou conversão de caixa às palavras.

python -m unittest tests.test_base.TestLista -v
python -c "from base import carregar_palavras; p = carregar_palavras(); print(len(p), p[:3], p[-1])"

Etapa 3 · juntos · TODO B2

O hash e a função de redução

Aula: p. 15, redução; p. 36, cores; p. 47, hash.

O hash do professor já está em base.py

def calcular_hash(senha: str) -> str:
    return hashlib.sha256(b"GBC083" + senha.encode("utf-8")).hexdigest()

Essa é a função do último slide. Antes da senha, ela acrescenta os bytes de GBC083. O encode("utf-8") converte a senha de texto para bytes, e hexdigest() devolve o hash escrito em hexadecimal, com 64 caracteres.

O slide mostra dois returns seguidos. Como a função termina no primeiro, vamos usar essa saída hexadecimal em todo o programa. Para conferir, o hash de "1234" deve ser:

5042f15f93d4f75df9cdff09d062d607eaa0140a930b9023c43ca7cc58609b8f
Esse prefixo funciona como um salt?

A diferença importante é que GBC083 será igual para todas as senhas do trabalho. Uma tabela construída com ele pode ser reutilizada entre os alvos. Com um salt diferente para cada senha armazenada, muda também o cálculo: a tabela feita para um salt não serve diretamente para outro. Isso se relaciona às p. 43–45, nas quais o professor apresenta salt e Argon2id.

A função de redução que vocês vão escrever

Agora temos um hash, mas precisamos de outra palavra para continuar a cadeia. É esse o papel de R, a função de redução: transformar o hash em uma posição da lista e devolver a palavra dessa posição.

Isso costuma causar confusão no começo. R não sabe qual palavra originou o hash. Ela só aplica uma regra que escolhe alguma entrada da lista. Se receber os mesmos argumentos outra vez, precisa escolher a mesma entrada, pois vamos usar essa regra para refazer as cadeias durante a busca.

Em base.py · reduzir

A função vai receber reduzir(h, coluna, palavras, modo="cores") e devolver uma palavra. Para que as duas partes usem a mesma regra, vamos escrevê-la assim:

  1. Confiram se a lista tem palavras, se a coluna é zero ou maior e se o modo é cores ou fixa. Para esses argumentos inválidos, usem ValueError.
  2. No modo cores, usem o número da coluna como cor. No modo fixa, usem sempre zero. Vamos comparar os dois depois.
  3. Montem o texto f"{cor}:{h}" e calculem o SHA-256 de seus bytes UTF-8, em hexadecimal. Vamos chamar esse resultado de “mistura”.
  4. Convertam a mistura para inteiro com int(mistura, 16). O resto da divisão por len(palavras) será a posição na lista.
  5. Devolvam a palavra dessa posição.

O f"..." insere os valores entre chaves no texto. % calcula o resto: 103 % 100 = 3. Para uma lista de N posições, o resto fica entre zero e N−1. Exemplo reduzido: mistura interpretada como 17 e lista ["uva", "sol", "mar"] → resto 2 → palavra "mar".

A p. 15 usa o resto da divisão para chegar a uma posição do dicionário. Aqui acrescentamos a mistura com SHA-256 para fazer a coluna participar da escolha. O professor pede reduções diferentes por coluna; essa fórmula é uma maneira de fazer isso. Ela também acrescenta uma aplicação de SHA-256 a cada redução, o que entra no tempo medido.

Usem hashlib.sha256 para essa mistura. A função hash() do Python pode dar resultados diferentes entre execuções quando recebe uma string, e precisamos conseguir refazer a mesma cadeia nos dois computadores.

Dica · qual SHA-256 é qual?

calcular_hash representa H, sempre com o prefixo do professor. Dentro de reduzir, a mistura é outra operação: aplique hashlib.sha256 diretamente ao texto da cor e do hash. Chamar calcular_hash para a mistura acrescentaria outro prefixo e sairia da convenção combinada.

python -m unittest tests.test_base -v

Um exemplo para conferir a implementação: com h = calcular_hash("1234") e a lista completa, as colunas 0, 1 e 2 devem devolver dixie, ark e creed. Se os resultados forem outros, confiram a ordem da lista, a montagem do texto e a conversão de hexadecimal para inteiro.

A coluna muda a regra de redução, mas duas colunas ainda podem acabar escolhendo a mesma palavra. Isso é possível porque estamos reduzindo muitos valores a apenas 7.776 opções. Vamos ver o efeito dessas coincidências nas cadeias.

Etapa 4 · juntos

Como funciona uma cadeia

Aula: p. 17, extremos; p. 24, hipóteses de posição; p. 29, reconstrução.

Escolhemos uma palavra da lista, calculamos seu hash e aplicamos a redução. Isso devolve outra palavra, com a qual podemos repetir o processo. Essa sequência é a cadeia. A cada passo, usamos a redução da coluna em que estamos.

Na escrita abaixo, p₀ é a palavra inicial, p₁ é a seguinte e assim por diante. R₀ é a redução da primeira coluna; R₁, a da segunda. Vamos chamar de largura t a quantidade de passos H→R.

p₀ → H → R₀ → p₁ → H → R₁ → … → pₜ

Depois de construir uma cadeia, guardamos só (p₀, pₜ), suas palavras de início e fim. Ao construir m cadeias, teremos m pares: essa é a altura da tabela. Embora os desenhos dos slides mostrem todas as colunas, no arquivo final ficam apenas esses pares.

Exemplo do slide 17

Vamos acompanhar a cadeia do slide, com uma cor para cada redução. Os hashes curtos servem só para facilitar a leitura. Cliquem em “Próximo passo” para ver o cálculo até o fim.

Começamos na palavra A.
Escolham um hash e cliquem no botão para acompanhar a busca.

Aqui já sabemos em qual posição cada hash aparece. No programa, teremos que testar as posições, começando pela última.

O que entra na contagem da largura

Reparem que calculamos H de A, D e Z, mas paramos assim que a última redução devolveu E. Portanto, essa linha tem largura 3: são três hashes, três reduções e quatro palavras. Ela permite procurar os hashes de A, D e Z. Para representar H(E), precisaríamos de E como entrada de H em alguma cadeia.

Isso vai fazer diferença nos laços do Python. Se a largura for 3, a construção deve executar três passos; na reconstrução, comparamos três hashes com o alvo.

Por que as cores ajudam?

Suponham que duas cadeias diferentes cheguem à palavra D. Se ambas usarem sempre a mesma redução, depois de D virá exatamente a mesma sequência. Os cálculos seguintes passam a repetir trabalho que já foi feito em outra cadeia. Dizemos que os caminhos se fundiram.

Com cores, precisamos saber também a coluna. Uma cadeia pode chegar a D na coluna 2 e usar R₂; outra chega a D na coluna 5 e usa R₅. Como as reduções são diferentes, a continuação pode ser diferente também.

Isso ajuda a reduzir as fusões, mas não elimina todas. Se as duas cadeias chegarem à mesma palavra na mesma coluna, terão a mesma continuação. E duas reduções diferentes ainda podem escolher a mesma palavra por coincidência. É com essa ressalva que devemos ler a explicação de “colisões pontuais” da p. 36.

Antes de escrever a busca, entendam este percurso

No exemplo, partindo do hash 11010 conseguimos seguir até E. O par guardado nos informa que uma cadeia termina em E e começa em A. Para descobrir a palavra que gerou 11010, precisamos então recomeçar de A: calculamos H(A), seguimos para D e verificamos H(D). Como H(D) é o alvo, encontramos D.

É o ponto da p. 29: seguimos para a direita nas duas vezes. Primeiro até o final; depois, do início até encontrar o hash procurado.

A1 · Uma linha primeiro

Em fim_da_cadeia

A função recebe a palavra de início e precisa devolver a palavra final. Use uma variável para acompanhar onde você está na cadeia. A cada repetição, calcule o hash dela e aplique a redução com o número da coluna. Depois de largura repetições, devolva a palavra em que parou. Se a largura for menor que 1, use ValueError.

Em pseudocódigo:

atual recebe inicio
para cada coluna entre 0 e t-1:
    h recebe o hash de atual
    atual recebe a redução de h nessa coluna
devolver atual
Dica · por onde começar o laço?

range(largura) produz 0, 1, …, largura−1. Faça um ensaio com largura 1: deve acontecer exatamente um hash e uma redução. Para depurar, imprima coluna, palavra atual, hash e próxima palavra. Remova essas impressões antes de medir.

python -m unittest tests.test_dupla.TestConstrucao.test_tres_passos -v

Esse teste usa versões pequenas de H e R, escolhidas para produzir A → B → C → D. Ele confere a ordem dos seus passos sem depender do SHA-256 ou da lista completa.

A2 · Construir várias linhas

Agora precisamos escolher os inícios. Vamos sorteá-los, mas queremos conseguir repetir o sorteio ao testar e comparar as tabelas. Para isso serve a semente: com o mesmo gerador, a mesma lista e a mesma semente, conseguimos repetir as escolhas.

Em construir
  1. Confira se 1 ≤ altura ≤ len(palavras) e se a largura é pelo menos 1. Se não forem, use ValueError.
  2. Importe random e sorteie os inícios com random.Random(semente).sample(palavras, altura). Esse gerador fica separado dos outros sorteios do programa.
  3. Para cada início, chame fim_da_cadeia com a largura e o modo recebidos. Acrescente o par início/fim à lista.
  4. Devolva os altura pares, na ordem em que os inícios foram sorteados.

O sample escolhe sem repetir: cada palavra aparece no máximo uma vez entre os inícios. Ela ainda pode reaparecer no meio das cadeias, porque isso depende das reduções. Para reproduzir uma tabela no computador do colega, vocês precisam usar também a mesma lista, regra de redução e versão de Python.

python -m unittest tests.test_dupla.TestConstrucao -v
Para conferir com o colega

Gere uma tabela com oito linhas de largura cinco. A lista devolvida deve ter oito pares. Mostrem um deles e refaçam sua cadeia à mão ou com prints, para conferir de onde saiu o final. Essa mesma lista já pode ser usada para testar a busca.

Etapa 6 · pessoa B · TODOs C1 e C2

Parte B: procurar um hash na tabela

Aula: p. 18–29 e p. 32. Agora cada coluna usa sua própria redução.

Se você ficou com a busca, abra busca.py. A função vai receber o hash que queremos procurar, a lista de palavras, os finais organizados num índice e a largura da tabela. C1 · Organizar os finais para consulta

Durante a busca, vamos precisar consultar vários finais. Em vez de percorrer a lista inteira de pares a cada vez, podemos organizá-los num dicionário Python. A chave será o final, e o valor será a lista de inícios que chegam até ele:

# Entrada ilustrativa de indexar:
[("A", "E"), ("B", "E"), ("C", "F")]

# Saída combinada:
{"E": ["A", "B"], "F": ["C"]}
Em indexar

Percorra os pares. Quando um final aparecer pela primeira vez, crie uma lista para ele; depois acrescente o início. Se esse final aparecer de novo, acrescente o novo início à lista que já existe. Ao terminar, devolva o dicionário. Para uma entrada sem pares, o resultado é {}.

Dica · um exemplo menor de agrupamento

Para agrupar pessoas por cidade: se cidade ainda não estiver no dicionário, crie grupos[cidade] = []. Depois use grupos[cidade].append(nome). A mesma ideia se aplica a finais e inícios.

python -m unittest tests.test_dupla.TestBusca.test_indice -v

C2 · Descobrir em qual posição o hash poderia estar

Vamos usar de novo o alvo 11010 e a tabela que guarda (A, E). No desenho sabemos que ele é h₁. O programa, porém, só recebe os pares e o alvo. Por isso precisa tentar as posições possíveis.

Comece supondo que o alvo era o último hash, h₂. Nesse caso, bastaria aplicar R₂ para chegar a um final. Se essa tentativa não confirmar uma senha, tente h₁: aplique R₁ ao alvo, calcule H da palavra obtida e depois aplique R₂. No exemplo, isso produz Z → 00110 → E. Por último, tente a posição h₀, que exige refazer a continuação inteira.

Perceba que a primeira operação sobre o alvo é sempre uma redução: ele já é um hash. A cor inicial depende da posição que estamos tentando. Só começamos pela cor zero quando supomos que ele era h₀.

Em buscar · localizar cadeias possíveis
para cada posição hipotética k, de t-1 até 0:
    use o hash-alvo como hash atual
    para cada coluna j de k até t-1:
        obtenha uma palavra com R_j do hash atual
        se ainda houver outra coluna:
            calcule H dessa palavra para continuar
    a última palavra é um final candidato
    procure TODOS os inícios associados a esse final
    confira cada um reconstruindo a cadeia

Na hipótese k=t−1, ocorre só uma redução. Na hipótese k=0, ocorre a continuação mais longa. Para um final inexistente no índice, continue para a próxima hipótese.

Refazer a cadeia para encontrar a palavra

Chegar a E nos dá um início para testar: A. Ainda precisamos verificar se o hash aparece na cadeia que começa em A. Uma continuação também pode chegar a E por coincidência, então encontrar o final, sozinho, não basta para devolver uma senha.

Em buscar · conferir cada cadeia encontrada
para cada início candidato:
    atual recebe inicio
    para cada coluna de 0 até t-1:
        h recebe H(atual)
        se h coincide com o alvo:
            devolver atual
        atual recebe R_coluna(h)
se nenhuma hipótese confirmar:
    devolver None

O return None fica depois de tentar todas as posições e todos os inícios associados. Se uma cadeia não contiver o alvo, ainda pode haver outra que contenha. Para largura menor que 1, use ValueError.

Dica 1 · limites dos laços

range(largura - 1, -1, -1) percorre as hipóteses do fim ao começo. range(k, largura) percorre a continuação para a direita. Na reconstrução, range(largura) começa sempre na cor zero. Mantenha nomes diferentes para a posição hipotética e a coluna atual.

Dica 2 · consultar um final que pode não existir

indice.get(final_candidato, []) devolve uma lista vazia se a chave não existir. Isso permite percorrer os candidatos sem capturar uma exceção. Não use apenas o primeiro início.

python -m unittest tests.test_dupla.TestBusca -v

Os testes conferem alvos no começo, no meio e no fim de uma cadeia. Também incluem um final que leva à cadeia errada e um final com mais de um início. Como nos testes da construção, usam funções pequenas no lugar de H e R. Na próxima etapa vamos juntar tudo com o SHA-256 real.

Uma chamada completa, para acompanhar juntos

No terminal, execute python para abrir o modo interativo. Cole o trecho abaixo só depois dos TODOs estarem implementados. Para sair, use exit().

from base import carregar_palavras, calcular_hash
from construcao import construir
from busca import indexar, buscar

palavras = carregar_palavras()

indice = indexar(pares)

A saída deve conter uma palavra e True. Aqui escolhemos um início da tabela de propósito. No experimento de eficácia, fazer isso inflaria os acertos: os alvos precisam ser sorteados de todo o dicionário.

Etapa 8 · juntos

Comparando altura, largura e número de acertos

Aula: p. 33, formatos; p. 34–36, repetição e cores; p. 42, custo do hash.

Agora que o programa funciona nos casos conhecidos, podemos voltar à pergunta do trabalho: o que muda quando alteramos o formato da tabela? Precisamos olhar tanto os acertos quanto o custo. Uma tabela pode encontrar mais senhas e, ao mesmo tempo, ocupar mais espaço ou demorar mais para responder.

O enunciado usa os termos eficácia e eficiência. Vamos medir eficácia pela proporção de alvos recuperados. Para discutir eficiência, vamos medir tempo de construção, tempo de busca e tamanho do arquivo da tabela.

Escolhi esses quatro formatos porque todos fazem 8.192 passos H→R na construção. Assim conseguimos comparar a distribuição do trabalho: muitas cadeias curtas ou poucas cadeias longas. A primeira tabela guarda 512 pares; a última, só 64. Em compensação, uma consulta à última pode precisar tentar muito mais posições até encontrar o alvo ou desistir.

São contagens do algoritmo, não medições de desempenho. A busca também reconstrói cadeias candidatas; esse trabalho adicional não está na soma exibida.

Dá para antecipar parte desse custo. Se a busca tentar todas as posições, terá que fazer continuações com 0, 1, 2, …, t−1 aplicações de H. A soma é t(t−1)/2, sem contar o trabalho de reconstruir cadeias candidatas. É por isso que aumentar bastante a largura pode encarecer a busca, mesmo que o total de passos da construção continue igual.

Talvez vocês tenham notado que 8.192 é maior que 7.776, o tamanho da lista. Isso não significa que todas as palavras foram cobertas: uma mesma palavra pode aparecer várias vezes nas cadeias. A p. 34 mostra esse problema. As reduções podem levar a caminhos repetidos mesmo sem existir nenhuma colisão de SHA-256.

O que cada número significa

taxa_acerto = acertos / 200. Multipliquem por 100 para porcentagem. construcao_s exclui escrita em disco; indexacao_s mede a preparação do índice, uma vez por tabela. buscas_s soma só as chamadas a buscar, sem gerar os alvos, salvar CSV ou verificar externamente os retornos.

sucesso_medio_ms é o tempo médio das buscas que encontraram uma senha; falha_media_ms, o das que tentaram todas as possibilidades e não encontraram. Se a célula estiver vazia, não houve consultas daquele tipo. Por exemplo, sem nenhum acerto, não há média de tempo de sucesso para calcular.

finais_distintos conta os finais diferentes no índice. Ele ajuda a observar as repetições, mas não informa sozinho quantas palavras aparecem nas cadeias. Já tabela_bytes mede o tamanho do JSON que guarda os pares. É uma medida do espaço em disco. A memória RAM usada durante a execução será maior, porque também contém a lista de palavras, o índice e os objetos do Python.

Comparar uma redução fixa com as cores

O modo fixa força todas as reduções a usar cor zero. O modo cores usa o índice da coluna. O programa repete os mesmos formatos, sementes e alvos nos dois modos. Com a mesma semente, ambos partem dos mesmos inícios; a diferença está nas reduções seguintes.

Assim podemos observar o efeito das cores mantendo o resto igual — uma comparação controlada. O modo fixa serve para comparar com a situação anterior à introdução das cores nos slides. O modo cores é a Rainbow Table pedida no trabalho. Comparem os resultados das três sementes antes de atribuir uma diferença pequena ao uso das cores.

Como abrir e comparar CSV sem instalar bibliotecas?

No VS Code, CSV é texto: a primeira linha contém os nomes das colunas. Para uma visualização tabular, importem resumo.csv no Excel/LibreOffice escolhendo vírgula como separador e ponto como decimal. Se abrir tudo numa única coluna, usem a importação em vez do duplo clique.

Etapa 10 · opcional

Adaptando para duas palavras

A lista continua com 7.776 entradas, mas o espaço de senhas passa a 7.776² = 60.466.176 pares ordenados. Com repetição permitida, "a a" vale; a ordem também importa. Adotem um espaço simples entre as palavras: "a a&p". O hash deve incluir exatamente esse espaço.

Guardar todas essas combinações em uma lista seria pesado. Podemos representá-las por um número x entre zero e N²−1 e só montar o texto quando precisarmos. Os índices das duas palavras são i = x // N e j = x % N. O operador // faz a divisão inteira, descartando a parte fracionária.

Mudanças necessárias · usem outra branch
  1. Mantenham carregar_palavras carregando a lista básica. Criem funções novas para converter posição de senha em texto e para reduzir ao espaço de duas palavras.
  2. Na redução, usem a mesma mistura por cor, mas tomem o resto por N². Separem esse número em dois índices e unam as palavras com um espaço.
  3. Sorteiem inícios por posições com sample(range(N * N), altura). Para alvos, usem um gerador independente e a mesma conversão.
  4. Adaptem construção e busca para usar essa representação e redução. Em uma versão simples, os pares ainda podem guardar os textos das senhas.
  5. Primeiro testem a conversão com uma lista pequena de três palavras: devem existir nove pares, com repetição e ordem. Depois verifiquem a recuperação de hashes presentes em cadeias curtas.
  6. Para uma primeira comparação, usem as mesmas alturas, larguras e quantidade de alvos do experimento com uma palavra. Anotem nos metadados que agora são duas palavras, separadas por um espaço.

O espaço cresceu bastante, mas a tabela continua fazendo o mesmo número de passos. Por isso pode acontecer de nenhum dos 200 alvos ser encontrado. Nesse caso, os testes com hashes conhecidos são especialmente úteis: eles ajudam a distinguir uma cobertura pequena de um erro na busca. Zero acertos na amostra não significa que nenhuma senha possa ser recuperada.

Essa adaptação fica para vocês: os arquivos fornecidos trabalham com uma palavra. Ela também retoma o que vimos no guia da prova sobre Diceware. Cada palavra sorteada acrescenta possibilidades à senha; ao passar de uma para duas, multiplicamos o espaço por 7.776.

Consulta

Glossário

Compromisso entre memória e tempo · time–memory tradeoff
Guardar menos informação e fazer mais cálculo para recuperá-la depois. A RT guarda extremos e reconstrói trechos; o custo inicial de preparação também conta.
Espaço de senhas · domínio
Conjunto de candidatos que a tabela pretende representar. Aqui, na trilha principal, é a lista de 7.776 palavras. Comprimento do hash e tamanho desse espaço são coisas diferentes.
Redução
Regra que transforma um hash em um candidato válido do espaço. Pode perder informação e não é a inversa do hash.
Cor · coluna
Identificador da redução usada numa posição da cadeia. Todas as linhas usam a mesma sequência de cores; não se sorteia uma cor secreta por linha.
Cadeia · início/fim · start/end
Sequência alternada de hashes e reduções. O par guardado contém a primeira e a última palavra. O miolo é recalculado durante a busca.
Altura e largura
Altura é o número de linhas guardadas. Neste guia, contamos a largura t pelos passos H→R de cada linha. São t hashes e t+1 palavras.
Colisão de redução
Dois hashes podem resultar na mesma palavra após R. Isso não implica hashes SHA-256 iguais. A redução escolhe num espaço muito menor que o dos hashes.
Fusão
Duas cadeias passam a ter um mesmo trecho restante. Nas tabelas com cores, encontrar a mesma palavra na mesma coluna provoca a mesma continuação.
Índice
Estrutura para localizar candidatos sem percorrer cada linha. Aqui é um dicionário que associa um final à lista de inícios correspondentes.
Falso candidato
Uma continuação chega a um final guardado, mas reconstruir a linha não encontra o hash-alvo. A confirmação pelo hash impede retornar uma senha incorreta.
Semente · seed
Valor que inicia um gerador pseudoaleatório reproduzível. É útil em experimentos. Não é um segredo nem uma fonte de aleatoriedade para criar senhas reais.
Comparação controlada
Mudar um aspecto e manter os demais comparáveis. Para observar as cores, mantemos inícios, alvos, formato e hash, alterando o modo da redução.
Eficácia, eficiência e cobertura
Eficácia aqui é a taxa de recuperação observada nos alvos. Eficiência envolve os custos medidos. Cobertura é a parcela do espaço representada; a taxa de uma amostra estima esse comportamento, sem ser necessariamente a cobertura exata.
Salt e KDF
Salt é um valor associado à senha para individualizar seu cálculo; ele não precisa ser secreto. KDF é uma função de derivação de chave; funções apropriadas para senhas, como Argon2id, permitem elevar o custo de tentativas. Esses conceitos aparecem no encerramento da aula.
Contrato de função · interface
O acordo sobre entradas, saídas e comportamento de uma função. Ele permite construir e buscar em arquivos distintos sem conhecer cada detalhe interno da outra parte.
Commit, branch, pull e push
Commit registra uma versão. Branch permite desenvolver separadamente. Pull traz atualizações do remoto e push envia commits. Um PR apresenta a mudança para revisão antes da integração.
